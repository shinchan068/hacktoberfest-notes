Part 3 — AI tools and agents

Separate coding tools from the models and systems behind them.

10 AI coding tools

In one line

Pick a coding tool by how you like to work. They overlap and their autonomy depends on settings, and you must always read what they changed.

  • Chat assistants explain and plan; editors offer visible edits; terminal agents work from the command line; app builders produce a first version.
  • Examples include ChatGPT, Cursor, Google Antigravity, Claude Code, Codex CLI, Aider and OpenCode. Categories overlap.
  • Autonomy depends on the tool and its settings. Read diffs, commands and generated code; you remain responsible for security and licensing.
Full notes & examples

These tools help you write code. They differ in where they live and how you work with them. They are not ranked from weak to strong, and many of them overlap: a lot of tools can chat, edit files, and run commands.

TypeExamplesHow you use it
Chat assistantChatGPT, Claude, GeminiExplain things, plan, debug pasted code. You copy-paste the code yourself.
AI code editor / GUI agentCursor, Windsurf, GitHub Copilot, Google AntigravityWorks inside an editor. Suggests and makes edits that you can see.
Terminal agentClaude Code, Codex CLI, Aider, OpenCodeWorks in the terminal. Reads files, edits code, runs commands and tests.
App builderLovable, Bolt, v0Generates a first version of an app from a description. Export and read the code.

An agent is an AI system that carries out a multi-step task by using tools (see Section 11).

Terminal agent vs GUI agent

A GUI (graphical user interface) is an app with windows and buttons. A diff is a view of exactly what changed in a file: lines removed and lines added.

Terminal agentGUI agent
Lives inYour terminalA window or panel in your editor
Shows changes asText diffs. Fast, and works naturally with GitVisual diffs. You click accept or reject.
Running commandsAsks you to approve each one, or runs on its own if you turn on an auto-approve modeDepends on its settings
Watch out forAuto-approve makes changes without asking, so review your commitsIt's easy to accept big changes without reading them
  • How much a tool does on its own depends on the tool and your settings, not on its type. There is no fixed order of "more autonomous" categories.
  • New to coding? A GUI tool is easier to follow. Comfortable in a terminal? Try a terminal agent. Either way, you read what changed.

Which tool for which job

JobGood fit
Understand an error or a conceptA chat assistant
Autocomplete and quick edits while codingAn AI code editor
A multi-step change across your repoAn agent (GUI or terminal)
A quick first version of a UIAn app builder, then export the code
Fully open and localAn open harness like OpenCode or Aider, with a local model

What AI tools must not decide for you

Generated code can contain made-up packages, unsafe commands, wrong versions, or leaked secrets. You are still responsible for the design, security, licensing, and checking that it works.

Check yourself

  1. Name one chat assistant, one GUI agent, and one terminal agent.

    Reveal answer
    For example ChatGPT, Cursor, and Claude Code.

  2. Does a terminal agent always ask before running a command?

    Reveal answer
    No. It can auto-approve if that's turned on.

  3. Is one category of tool always more autonomous than another?

    Reveal answer
    No. It depends on the tool and its settings.

11 Model, harness, runner, agent

In one line

The model produces the output, the runner serves it, the harness gives it tools and context, and an agent is the whole thing working in a loop.

  • The model produces the output. A runner loads and serves it. A harness supplies instructions, tools, context and permissions.
  • An agent combines a model and harness to work through a task with tools. The model cannot edit files without provided and permitted file tools.
  • OpenCode and Aider are open-source harness options; Ollama is a runner. A useful harness includes controls, action logs and ways to check results.
Full notes & examples

These four words get mixed up. They are different things.

WordWhat it isExample
ModelProduces the output from the inputGemma, Llama
RunnerLoads a model and serves it to appsOllama, llama.cpp
HarnessThe software around a model: instructions, tools, memory, actionsClaude Code, OpenCode, Aider
AgentA model plus a harness, working step by step with tools on a taskA coding agent fixing a bug

The harness

A harness gives the model:

  • Prompts and system instructions: what to do and what not to do.
  • Tools: search, files, Git, GitHub, the terminal.
  • Memory or context: what the model can see.
  • Actions: running code, calling APIs.

Analogy: the model is the engine and the harness is the car built around it. The same engine can go into different cars. Real systems vary, but this helps you remember the roles.

A model on its own can't open your files or use GitHub. The harness has to provide those tools and allow them to be used.

The agent loop

An agent works in a loop: get the goal → look at the context → choose the next action → use a tool → look at the result → update the plan → repeat or stop.

User: "Fix the failing login test"
Agent reads test output → reads the code → edits it
→ runs tests → checks result → reports changes

Chatbot vs agent

A simple chatbot mainly answers messages. An agent can carry out multi-step tasks with tools, keep track of progress, and check its work. Some chatbots have tools too, so the difference is in what the system does, not a fixed product type.

What makes a good harness

  • Clear instructions, including limits.
  • The right files and context.
  • Useful tools: files, Git, terminal, tests.
  • Permission controls and a log of important actions.
  • A way to read tool results and decide the next step.

Open options: OpenCode (an open-source agent that works with many models) and Aider (an open-source pair programmer that works closely with Git). With both, you bring your own model, which can even be a local one served by Ollama.

Check yourself

  1. Is Ollama a model, a runner, or a harness? What about OpenCode?

    Reveal answer
    Ollama is a runner. OpenCode is a harness.

  2. Why can't a model edit your files by itself?

    Reveal answer
    The harness must provide and allow file tools.

  3. Write down the steps of the agent loop.

    Reveal answer
    Goal → look at context → choose action → use tool → look at result → update plan → repeat or stop.
