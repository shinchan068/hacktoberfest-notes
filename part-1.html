01 Software basics you will keep hearing

In one line

The frontend is what users see and the backend runs on a server. Programs talk to each other through APIs, sending requests and getting responses, usually in JSON.

  • Frontend = the interface; backend = server-side rules, data and services.
  • An API request has a method, URL, headers and sometimes a body. JSON stores keys and values.
  • 200 = OK; 400 = bad request; 401 = missing or wrong key; 404 = not found; 429 = slow down; 500 = server error.
Full notes & examples

Before AI, a few everyday software words.

  • Program / app: a set of instructions a computer runs. A product is an app built for real users.
  • Frontend: the part of an app the user sees and clicks, for example a web page in the browser.
  • Backend: the part that runs on a server (a computer that is always on and answers requests). Users don't see it. It stores data, checks rules, and talks to other services.
  • Terminal (or command line): a text window where you type commands instead of clicking.
  • IDE (Integrated Development Environment): a code editor with extra tools, for example VS Code.
  • Library / package: code someone else wrote that you can install and reuse. Dependencies are the packages your project needs.

What is an API?

An API (Application Programming Interface) is a fixed way for one program to ask another program to do something. On the web, this usually happens over HTTP, the same system your browser uses to load pages.

Every API call is a request and a response:

  • Request: you send a method (GET to read something, POST to send something), a URL (the address), headers (extra information, such as your API key), and sometimes a body (the data you are sending).
  • Response: you get back a status code and usually some data.

A small example. Your app asks a weather service for today's weather:

GET https://api.example.com/weather?city=Hyderabad

The service answers with status 200 and this data:

{
  "city": "Hyderabad",
  "temp_c": 29,
  "condition": "cloudy"
}

Common status codes:

CodeMeaning
200OK, it worked
400Bad request: you sent something wrong
401Unauthorized: missing or wrong key
404Not found: wrong address
429Too many requests: slow down
500The server had an error

An endpoint is one specific URL that an API answers on, like /weather.

What is JSON?

JSON (JavaScript Object Notation) is a simple text format for structured data. It is written as keys (names) and values, like {"room": "B-204", "urgent": true}. Almost every API, including AI model APIs, sends and receives JSON.

Check yourself

  1. What is the difference between the frontend and the backend?

    Reveal answer
    The frontend is what users see. The backend runs on a server and handles data and logic.

  2. Name the parts of an API request.

    Reveal answer
    Method, URL, headers, and body.

  3. What does status code 401 usually mean?

    Reveal answer
    A missing or wrong key (unauthorized).

02 What an AI model is

In one line

A model is trained software whose learned numbers (weights) turn input into output. Training teaches it, inference uses it, and it also needs its architecture, tokenizer and software to run.

  • Training adjusts learned numbers called weights; inference uses them on new input. A 4B model has about four billion parameters.
  • A model also needs its architecture, tokenizer, configuration and compatible software.
  • An LLM predicts the next piece of text. Common weight files include .safetensors and .gguf.
Full notes & examples

An AI model is a trained program that turns input into output. The input might be text, an image, or audio. The output might be an answer, a label, or a summary.

A normal program follows rules a person wrote: "if the message contains 'urgent', mark it high". A model learns its behaviour from examples instead.

Training and inference

  • Training is how a model learns. It is shown a huge number of examples, and its internal numbers are adjusted again and again until its outputs get better. Training big models takes a lot of data, time and powerful computers.
  • Inference means using an already trained model on new input. When your app sends a complaint to a model and gets a label back, that is inference. As an app builder, you will almost always do inference, not training.

Weights (parameters)

Weights, also called parameters, are the numbers a model learned during training. A modern language model can have billions of them. When you read "a 4B model", it means about 4 billion parameters.

Small example (toy spam filter): During training, a model sees thousands of emails marked "spam" or "not spam". It learns that words like "prize" and "winner" push towards spam, and a word like "meeting" pushes away from it. Those learned pushes are stored as weights. Nobody typed them in as a rule list.

The other parts a model needs

Weights alone are not enough to run a model. You also need:

  • Architecture: the design of the model, meaning how its layers are arranged and how the numbers are combined.
  • Tokenizer: the part that splits text into tokens (small chunks of text, see Section 14) and turns them into numbers the model can process.
  • Configuration: settings such as the model's size and its maximum input length.
  • Compatible software to load and run it (a runner, see Section 3).

Model files

Weights are saved in files. Two common formats:

  • model.safetensors: a common, safe format for model weights.
  • model.gguf: a format often used to run models on your own laptop.

LLMs

An LLM (Large Language Model) is a model trained on a very large amount of text. It works by predicting the next piece of text. Chat assistants and coding tools are built on LLMs. In these notes, "model" usually means an LLM.

Check yourself

  1. What is the difference between training and inference?

    Reveal answer
    Training adjusts the weights by learning from examples. Inference uses the trained model on new input.

  2. What does "7B" tell you about a model?

    Reveal answer
    It has about 7 billion parameters.

  3. Name two things besides weights that you need to run a model.

    Reveal answer
    Any two of: architecture, tokenizer, configuration, compatible software.

03 Where models run: local, cloud, API

In one line

You can run a model locally with a runner like Ollama, on a cloud server, or through a hosted API. Smaller and quantized models are easier to run.

  • Local: your computer, limited by its memory and speed. Cloud: a rented server you manage. Hosted API: a provider runs it for you.
  • Ollama is a local runner, not a model. llama.cpp is another runner; Transformers is a Python library.
  • Quantization uses fewer bits per weight: smaller files and often faster inference, with a quality trade-off. Check the exact model and license.
Full notes & examples

There are three common ways to use a model.

WayWhere it runsGoodWatch out
LocalYour own laptop or PCFree to run, works offline, your data stays on your machineNeeds enough memory, and big models are slow or won't fit
Your own cloud serverA rented computer, often with a GPUCan run bigger modelsCosts money, and you have to set it up
Hosted APIA provider's serversEasiest to start, and fastNeeds an API key and internet, may cost money, and your data goes to the provider

A GPU (Graphics Processing Unit) is a chip that does many calculations at once. It makes models run much faster.

Runners

A runner is software that loads a model's files and serves the model to your app. Some common ones:

  • Ollama: an easy local runner. You download a model with one command, and it runs on your computer. It also gives your app a local API to call. Ollama is a runner, not a model.
  • llama.cpp: a fast, lightweight runner for .gguf files.
  • Transformers: a Python library from Hugging Face (see Section 5) for loading and running models in code.

Typical Ollama commands (look up the exact model names on ollama.com):

ollama pull <model-name>     # download a model
ollama run <model-name>      # chat with it in the terminal
ollama list                  # see models you have downloaded

While Ollama is running, your app can call it like any other API, at http://localhost:11434. localhost means "this same computer".

Size and speed

  • Smaller models (a few billion parameters) often run on a normal laptop. Bigger models need more memory or a GPU.
  • Quantization stores the weights using fewer bits per number. This makes the file smaller and faster to run, with a small loss in quality. You will often see versions labelled like Q4.
  • For a simple task such as sorting short messages, a small model is often good enough. Test it before reaching for a bigger one.

Hosted does not always mean closed

A provider can host an open-weight model (see Section 4) and give you an API for it. The model is still open-weight, because its weights can be downloaded elsewhere. Using it through an API doesn't change that. Always check and write down the exact model and its license.

Check yourself

  1. Give one advantage and one disadvantage of running a model locally.

    Reveal answer
    For example: it's free and private, but it's limited by your laptop's memory and speed.

  2. Is Ollama a model?

    Reveal answer
    No. It's a runner.

  3. What does quantization do?

    Reveal answer
    It stores the weights with fewer bits, so the model is smaller and faster, with a small quality loss.

04 Open-source vs open-weight vs closed models

In one line

Open-weight means you can download and run the weights under a license. Open-source AI also gives you the code and data information under open terms to use, study, modify and share. Closed means you only get the outputs.

  • Open-source AI provides the necessary model components, code and information (including data information) under open terms to use, study, modify and share.
  • Open-weight means downloadable weights that run with compatible software under the model’s license. Training code and data may stay private.
  • Closed models provide outputs through an app or API without downloadable weights. API-only availability is not open-weight; a hosted open-weight model can still have downloadable weights elsewhere.
Full notes & examples

"Open-source model" and "open-weight model" sound alike, but they mean different things. The difference is about what you can get and what you are allowed to do.

Open-source AI model

An open-source AI model makes the necessary parts of the model available under open terms:

  • its weights and parameters,
  • the code to train and run it,
  • and information about the training data, detailed enough that a skilled person could build a similar model.

"Open terms" means you are allowed to use, study, modify, and share it.

This is the meaning used by the Open Source Initiative (OSI), the group that maintains the official definition of "open source", in its Open Source AI Definition. Two things it does not say:

  • It does not say every single file must be public.
  • It does not say every piece of original training data must be published. It requires enough information about the data.

Open-weight model

An open-weight model is one whose trained weights are published, so you can download them and run them with compatible software under the provider's license. Its training data and training code may stay private.

  • This is the most common kind of "open" model. Examples: Gemma (Google), Llama (Meta), Mistral, Qwen.
  • Using a model only through an API does not make it open-weight. Open-weight means you can download the weights.
  • An easy way to remember it: you get the trained result, not necessarily the full recipe.

Closed model

With a closed model, you can only get its outputs, through an app or an API. You cannot download its weights.

Open-source AIOpen-weightClosed
Download the weightsYesYesNo
Training codeYes, under open termsMaybe privateNo
Training-data informationYes, enough to build a similar modelMaybe privateNo
TermsOpen: use, study, modify, shareThe provider's license, which may have limitsThe provider's terms of service
Can run on your own machineYesYesNo

Common mistakes:

  • "It's free to use" does not mean it is open source.
  • "It's listed publicly" does not mean it is open source.
  • "I call it through an API" does not mean it is open-weight.
  • When you aren't sure, a safe way to say it is: "We use open-weight model X," with a link to its license.
Check yourself

  1. A company lets you use its model only through an API. Is the model open-weight?

    Reveal answer
    No. API-only access isn't open-weight.

  2. Does the OSI definition require every piece of training data to be public?

    Reveal answer
    No. It requires enough information about the data.

  3. Is "free to use" the same as "open source"?

    Reveal answer
    No.

05 Model families, model cards, model IDs and Hugging Face

In one line

A family is a brand, a model ID is one exact model, and the model card tells you how to use it and under what license. Hugging Face is where many models are shared.

  • A family contains related models. A model ID names one exact version and size. Licenses can differ within a family.
  • Record the exact model ID and version, source URL, and license or terms. Read the model card for tasks, limits and setup.
  • Hugging Face hosts models, datasets and demos. Gated models require sign-in and acceptance of their terms before download.
Full notes & examples

Model families

A model family is a group of related models from one maker. Each family has many versions and sizes, and they don't all share the same license.

FamilyMakerNote
GemmaGoogleOpen-weight, under Google's own Gemma terms
LlamaMetaOpen-weight, under Meta's community license. Not a classic MIT license, so read it.
QwenAlibabaMany open-weight versions
MistralMistral AIHas open-weight versions, and some are Apache-2.0
DeepSeekDeepSeekHas open-weight releases. Read the license.
PhiMicrosoftSmall models, easier to run on a laptop

Model card

A model card is the official page for a model. It tells you what the model is for, its size, what languages or tasks it handles, its limits, its license, and how to run it. Read it before you use a model.

Model ID

A model ID is the exact name of one specific model version, not only the family name. "Gemma" is a family. A model ID names one size and version of it. Always write down:

  • the exact model ID and version,
  • where you got it (the source URL),
  • its license or terms.

Hugging Face

Hugging Face is a website where people share models, datasets (collections of data), and demo apps. Each model has its own page with a model card and files. Model IDs there look like owner/model-name, for example google/<model-name>.

  • Some models are gated: you have to log in and accept the license before you can download them.
  • The Transformers library can download a model by its ID and run it in Python.
Check yourself

  1. Why is "we use Gemma" not specific enough?

    Reveal answer
    Gemma is a family with many models. You need the exact model ID.

  2. What three things should you record about any model you use?

    Reveal answer
    The exact model ID and version, the source URL, and the license.

  3. What is a gated model?

    Reveal answer
    A model you must log in and accept the license for before downloading.
