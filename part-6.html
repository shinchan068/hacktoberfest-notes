18 Secrets, API keys and environment variables

In one line

Code reads secrets from environment variables. Real keys live in a git-ignored .env, teammates get .env.example, and a leaked key gets rotated right away.

  • Secrets include API keys, access tokens, passwords, cookies and private database connection strings.
  • The backend reads environment variables. A local .env can load them, but is plain text, not encrypted. Commit only fake values in .env.example.
  • Never expose private keys in browser code or shared prompts. On deployment use secret settings. Revoke or rotate leaked keys immediately; deletion from the latest commit is not enough.
Full notes & examples

A secret is any value that unlocks an account or a resource:

  • API keys: for example a key for a hosted model API.
  • Access tokens: for example a GitHub token or a Slack bot token.
  • Passwords and cookies: anything that signs you in.
  • Database passwords and private connection strings.

Environment variables

An environment variable is a named value your program reads from the computer it runs on, instead of writing it in your code. Your code says "give me MODEL_API_KEY", and the value comes from outside.

  • In JavaScript (Node.js): process.env.MODEL_API_KEY
  • In Python: os.environ["MODEL_API_KEY"]

The .env pattern

  • .env: a file of NAME=value lines with your real keys, kept on your machine only. A small library (such as dotenv) loads it into environment variables. It is not encrypted. It's just a convenient place to keep the values.
  • .gitignore: lists .env so Git never tracks it.
  • .env.example: the same names with fake values. It is safe to commit, so teammates know which keys they need.
    • # .env  (real values; never commit)
MODEL_API_KEY=replace_with_real_private_key
DATABASE_URL=replace_with_private_connection_string
# .gitignore
.env
.env.local
# .env.example  (safe to commit)
MODEL_API_KEY=your_key_here
DATABASE_URL=your_database_url_here

    Golden rules

  • Never commit secrets to GitHub.
  • Never paste keys into public chats or groups, screenshots, issues, or prompts you share.
  • Never put a private key in frontend (browser) code, because anyone can read it. Call the API from your backend.
  • When you deploy (put your app online), use the hosting platform's environment variable or secret settings.

Leaked a key?

Revoke or rotate it immediately. That means cancelling the key or replacing it with a new one on the provider's website. Deleting the commit is not enough, because the key stays in Git history. Then check for misuse and update every place that used the old key.

Check yourself

  1. Which is safe to commit: .env or .env.example?

    Reveal answer
    .env.example.

  2. You pushed a key and deleted it in the next commit. Are you safe?

    Reveal answer
    No. The key is still in Git history, so rotate it now.

  3. Why shouldn't an API key be in browser code?

    Reveal answer
    Anyone can read browser code and steal the key.

19 Security basics for AI apps

In one line

Check everything that comes in, including the model's own output, and treat outside text as data, not instructions.

  • Validate user input and model output before using or saving them. Valid JSON can still contain wrong values.
  • Prompt injection puts instructions in untrusted messages, files or websites. Treat that content as data, not commands.
  • Limit access, protect personal data, document repeatable setup and pin important dependency versions.
Full notes & examples
  • Validate input: check what users send before using it.
  • Validate model output: a model can return broken JSON, missing fields, or wrong values. Check the output before saving or showing it.
  • Prompt injection: text from users, files, or websites can contain hidden instructions like "ignore your rules and…". Treat outside content as untrusted data, not as commands.
  • Least privilege: give tokens and tools only the access they need.
  • Private data: don't send real personal or sensitive information to services you haven't checked or that haven't been approved.
  • Repeatable setup: write down the install steps, and pin important dependency versions (fix them to exact versions) so the project works the same on another machine.
Check yourself

  1. What is prompt injection?

    Reveal answer
    Hidden instructions inside outside text that try to control the model.

  2. Why should you validate the model's output?

    Reveal answer
    It can be broken or wrong, and bad data could crash the app or mislead users.
