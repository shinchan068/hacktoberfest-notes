Part 1 — Foundations

In one line

Start with software, APIs and models. Learn what “open” actually means.

1. Software basics you will keep hearing

Check yourself

  1. What is the difference between the frontend and the backend?

    Reveal answer
    The frontend is what users see. The backend runs on a server and handles data and logic.

  2. Name the parts of an API request.

    Reveal answer
    Method, URL, headers, and body.

  3. What does status code 401 usually mean?

    Reveal answer
    A missing or wrong key (unauthorized).

2. What an AI model is

Check yourself

  1. What is the difference between training and inference?

    Reveal answer
    Training adjusts the weights by learning from examples. Inference uses the trained model on new input.

  2. What does "7B" tell you about a model?

    Reveal answer
    It has about 7 billion parameters.

  3. Name two things besides weights that you need to run a model.

    Reveal answer
    Any two of: architecture, tokenizer, configuration, compatible software.

3. Where models run: local, cloud, API

Check yourself

  1. Give one advantage and one disadvantage of running a model locally.

    Reveal answer
    For example: it's free and private, but it's limited by your laptop's memory and speed.

  2. Is Ollama a model?

    Reveal answer
    No. It's a runner.

  3. What does quantization do?

    Reveal answer
    It stores the weights with fewer bits, so the model is smaller and faster, with a small quality loss.

4. Open-source vs open-weight vs closed models

Check yourself

  1. A company lets you use its model only through an API. Is the model open-weight?

    Reveal answer
    No. API-only access isn't open-weight.

  2. Does the OSI definition require every piece of training data to be public?

    Reveal answer
    No. It requires enough information about the data.

  3. Is "free to use" the same as "open source"?

    Reveal answer
    No.

5. Model families, model cards, model IDs and Hugging Face

Check yourself

  1. Why is "we use Gemma" not specific enough?

    Reveal answer
    Gemma is a family with many models. You need the exact model ID.

  2. What three things should you record about any model you use?

    Reveal answer
    The exact model ID and version, the source URL, and the license.

  3. What is a gated model?

    Reveal answer
    A model you must log in and accept the license for before downloading.

Part 2 — Open source, licenses and Git

In one line

Understand licenses and make a useful first contribution.

6. How open-source software works

Check yourself

  1. What is the difference between a fork and a branch?

    Reveal answer
    A fork is your own copy of someone's repo. A branch is a line of work inside one repo.

  2. Which file explains how to contribute to a project?

    Reveal answer
    CONTRIBUTING.md.

  3. What makes a good first PR?

    Reveal answer
    Small, focused, tested, actually needed, and explained clearly.

7. Licenses

Check yourself

  1. A repo is public but has no LICENSE. Can you freely copy its code?

    Reveal answer
    No. There is no automatic permission.

  2. When do GPL's "share the source" duties apply?

    Reveal answer
    When you distribute the program or a changed copy.

  3. Your app is MIT and uses Gemma. Is Gemma now under MIT?

    Reveal answer
    No. Gemma keeps its own terms.

8. Git and GitHub

Check yourself

  1. What is a commit?

    Reveal answer
    A saved snapshot of changes, with a message.

  2. Which command shows what will go into your next commit?

    Reveal answer
    git status.

  3. Why should .env be listed in .gitignore?

    Reveal answer
    So real keys never get committed.

9. Project structure and the README

Check yourself

  1. Name four things a README should contain.

    Reveal answer
    Any four: what it does and for whom, features and the model's role, model ID, source and license, setup steps, how to run and test, limitations, the app license.

  2. Why commit .env.example but not .env?

    Reveal answer
    .env.example holds only fake values that show what's needed. .env holds real secrets.

Part 3 — AI tools and agents

In one line

Separate coding tools from the models and systems behind them.

10. AI coding tools

Check yourself

  1. Name one chat assistant, one GUI agent, and one terminal agent.

    Reveal answer
    For example ChatGPT, Cursor, and Claude Code.

  2. Does a terminal agent always ask before running a command?

    Reveal answer
    No. It can auto-approve if that's turned on.

  3. Is one category of tool always more autonomous than another?

    Reveal answer
    No. It depends on the tool and its settings.

11. Model, harness, runner, agent

Check yourself

  1. Is Ollama a model, a runner, or a harness? What about OpenCode?

    Reveal answer
    Ollama is a runner. OpenCode is a harness.

  2. Why can't a model edit your files by itself?

    Reveal answer
    The harness must provide and allow file tools.

  3. Write down the steps of the agent loop.

    Reveal answer
    Goal → look at context → choose action → use tool → look at result → update plan → repeat or stop.

Part 4 — Talking to models

In one line

Give clear instructions, manage context and verify the output.

12. Prompts

Check yourself

  1. List four things that can be part of a prompt.

    Reveal answer
    The task, extra rules, earlier messages, and attached files.

  2. What is the difference between a system prompt and a user prompt?

    Reveal answer
    The system prompt is the app's standing instructions. The user prompt is the actual message.

13. Prompt engineering: four habits

Check yourself

  1. What is few-shot prompting?

    Reveal answer
    Giving one or two small examples of the output you want.

  2. What are the four parts of Habit 2?

    Reveal answer
    Role, context, format, why.

  3. Why ask for null instead of a guessed room number?

    Reveal answer
    So the model doesn't invent data; an honest blank is better than a wrong room.

14. Tokens and the context window

Check yourself

  1. Roughly how many English words fit in 100 tokens?

    Reveal answer
    About 75.

  2. Does the model's reply use context window space?

    Reveal answer
    Yes.

  3. Your chat has become long and confused. What should you do?

    Reveal answer
    Start a fresh chat and share only what matters.

15. Hallucinations

Check yourself

  1. Why do models hallucinate?

    Reveal answer
    They predict text that sounds right and don't automatically check facts.

  2. What should you check before running pip install on a package an AI suggested?

    Reveal answer
    That the package really exists on PyPI or npm, by reading its official page.

Part 5 — Extending agents

In one line

Understand what skills and MCP add to an agent.

16. Agent skills (SKILL.md)

Check yourself

  1. What file must every skill have?

    Reveal answer
    SKILL.md.

  2. Does adding a skill give an agent access to GitHub?

    Reveal answer
    No.

  3. What makes a skill good?

    Reveal answer
    A specific trigger, concrete steps, and a result you can check.

17. MCP (Model Context Protocol)

Check yourself

  1. What is the difference between an MCP host and an MCP server?

    Reveal answer
    The host is the AI app. The server offers tools to it.

  2. How is a skill different from an MCP server?

    Reveal answer
    A skill gives steps to follow. An MCP server provides a connection to an outside tool.

  3. What does "least privilege" mean?

    Reveal answer
    Giving only the access that is really needed.

Part 6 — Safe engineering

In one line

Keep secrets private and validate data at every boundary.

18. Secrets, API keys and environment variables

Check yourself

  1. Which is safe to commit: .env or .env.example?

    Reveal answer
    .env.example.

  2. You pushed a key and deleted it in the next commit. Are you safe?

    Reveal answer
    No. The key is still in Git history, so rotate it now.

  3. Why shouldn't an API key be in browser code?

    Reveal answer
    Anyone can read browser code and steal the key.

19. Security basics for AI apps

Check yourself

  1. What is prompt injection?

    Reveal answer
    Hidden instructions inside outside text that try to control the model.

  2. Why should you validate the model's output?

    Reveal answer
    It can be broken or wrong, and bad data could crash the app or mislead users.

Part 7 — Building an AI app

In one line

Follow one complete AI feature from messy input to tested output.

20. Worked example: Hostel Complaint Triage

Check yourself

  1. List the five steps of the MVP flow.

    Reveal answer
    Submit message → backend sends it to the model → model returns JSON → backend validates it → dashboard shows the card and allows correction.

  2. In the code sketch, why is JSON.parse not the last step?

    Reveal answer
    The model's JSON can still have missing or wrong values, so you must validate it.

21. Testing an AI app

Check yourself

  1. Name three tricky inputs to test in a triage app.

    Reveal answer
    Any three: no room number, slang or typos, duplicates, mixed urgency signals.

  2. What should your app do if the model returns invalid JSON?

    Reveal answer
    Show a clear error or retry, and not crash or save bad data.
